# Moerise 检索与随机漫步

Moerise 内置检索服务（`SearchService`），为 Web、Android 客户端以及外部只读 REST/MCP 接口提供关键词检索、向量语义检索与混合检索。

Web 与 Android（`/api/app/v1/search`）默认使用 `keyword` 模式，所有检索模式均直接查询本地 `index.sqlite3`；外部机器 REST 与 MCP 默认使用 `hybrid` 模式，并在返回前核验 Memos 来源。

## 一、三种检索模式

| 模式 (`mode`) | 底层实现 | 依赖向量模型 | 说明 |
| --- | --- | --- | --- |
| `keyword` | SQLite FTS5 中文预分词 | 否 | 匹配中文短语、英文词与标签，无需模型即可使用。 |
| `semantic` | 向量余弦相似度 | 是 | 按语义相近程度召回表述不同但含义相关的笔记。 |
| `hybrid` | FTS5 + 向量 + RRF 融合 | 可选 | 结合关键词、标签与语义得分；未启用向量模型时回退为关键词与标签排序。 |

## 二、多通道召回与混合排序算法

### 1. 中文预分词全文索引 (FTS5)
- **中文分词**：对连续中文生成单字与相邻双字（Bi-gram），英文和数字整词转小写，不做词干还原。
- **跨块衔接**：分块边界处的相邻中文双字同时写入相邻两块，避免短语落在切分位置时漏匹配。
- **参数化查询**：查询词转义为参数化 FTS5 表达式，避免特殊符号触发语法错误。

### 2. 向量语义扫描
- 活跃代次的 `float32` 向量矩阵常驻内存，查询时直接执行多协程分片余弦相似度计算，无需重复读盘。

### 3. 多通道 RRF 排名融合 (Reciprocal Rank Fusion)
混合检索分别从关键词、标签和语义通道召回前 100 个候选片段，按 RRF 公式计算综合分：

```math
\operatorname{RRF}(d) = \sum_{m \in \{\mathrm{keyword},\mathrm{tag},\mathrm{semantic}\}} \frac{1}{60 + \operatorname{rank}_m(d)}
```

- 同一篇笔记取最高片段分作为整篇得分；
- 返回排序结果，附带命中片段与命中的信号类型（`keyword`、`semantic` 或 `tag`）。

## 三、来源复查保障 (Source Verification)

- **客户端接口（`/api/app/v1`）**：直接读取本地同步索引 `index.sqlite3`（写操作直通 Memos 后即时刷新本地投影，后台按轮询周期同步外部改动），减少高频检索对 Memos 的回源开销。
- **外部机器接口（`/api/ext/v1` 与 `/mcp`）**：召回候选后通过 Memos 官方 API 核验笔记是否存在、归属绑定作者及状态是否符合过滤条件；已删除或归属变化的条目会被剔除并异步修正本地投影，来源不可用时返回错误。

## 四、随机漫步 (Random Walk)

随机漫步基于向量相似度在历史笔记间跳转：

1. **起点选择**：从指定笔记出发，或随机选取一篇正常笔记作为起点。
2. **候选抽取**：按与当前笔记的向量相似度构建相关候选池。
3. **受控随机步进**：在候选池中按概率随机抽取下一篇笔记，不限定同一标签。
4. **单次漫步去重**：由调用方传入已访问路径，服务端排除重复资源名，不写入持久阅读历史。
5. **边界提示**：相关候选全部访问完后返回边界提示，可重新开启新的漫步。

随机漫步需要 Embedding 已启用且索引就绪；相关笔记接口（`/api/ext/v1/notes/{memo_id}/related`）结合关键词、标签与已有文档向量召回，不额外调用查询模型。
