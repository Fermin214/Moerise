# 检索与发现

检索、相关笔记和语义漫步共用一个业务服务，通过 REST、MCP 与飞书访问。默认不包含归档笔记，只处理绑定作者的内容。输出前复查来源身份、作者、原文、状态及内容摘要；来源故障时返回错误，不输出索引中的旧正文。

## 模型与索引

`embedding` 与 `llm` 独立。仅填写 embedding 即可使用本阶段能力，无需 LLM；不填写模型时仍可使用中文关键词、标签搜索和随机漫步。

```json
{
  "embedding": {
    "protocol": "openai-compatible",
    "base_url": "https://your-provider.example/v1",
    "api_key": "your-embedding-api-key",
    "model": "your-embedding-model",
    "dimensions": 0,
    "batch_size": 16,
    "timeout_seconds": 30,
    "max_chunks": 20000
  }
}
```

`base_url` 包含协议路径，适配器在其后追加 `/embeddings`，支持 HTTP(S)，禁止地址内凭据、查询参数及片段，不跟随重定向。模型请求使用环境代理及正常 TLS 证书校验。自托管且无需鉴权的模型可将 `api_key` 留为 `null`。配置模型后会向该提供商发送绑定作者的笔记分块和语义查询；基础 Memos PAT 不会发送给模型。

`dimensions=0` 表示从首次响应确认维度，不向提供商发送 dimensions 字段。显式填写时要求响应维度一致；支持 1 至 4096 维。`batch_size` 为 1 至 64，每轮处理至多该数量的笔记，单条长笔记按相同上限分批请求。超时为 1 至 90 秒，分块上限为 1 至 100000。模型返回的序号、数量、维度及数值必须可信，拒绝重复序号、零向量及非有限数值。

短笔记不超过 1000 个 Unicode 码点时整条索引。长笔记优先在段落边界切分，过长段落按 1000 个码点硬切，空白块省略；每块保存起止位置和内容 SHA-256。向量空间记录提供商地址、模型、实际维度及 `paragraph-runes-v1-1000` 分块版本。向量归一化后以连续 float32 数据存入 `index.sqlite3`。

首次成功全量同步后，独立后台循环处理缺失或正文摘要变化的笔记，每条完成后持久保存。单条正文在模型调用中发生变化或删除时不发布旧向量；已完成部分在重启后复用。仅更新标签、时间或归档状态不重新生成向量。失败保留错误代码并在 30 秒后重试，不阻塞同步、记录或回顾。

更换提供商地址、模型、显式维度或分块版本后构建独立空间，所有当前笔记完成后在同一事务中切换，并清理旧空间；构建期间不把新查询向量与旧模型混合。服务重启读取持久进度，API Key 轮换不触发重建。更换 LLM 不影响向量。

`GET /api/ext/v1/search/index` 返回 `disabled`、`pending`、`building` 或 `active`，以及实际维度、分块数、待处理笔记数、裸向量字节数和最近错误。`active` 表示该模型已启用，之后的正文变更通过 `pending_memos` 查看。`/health/ready` 保持来源同步的就绪语义；检索就绪单独查看该接口。

使用现有 `rebuild-index` 命令可重建投影、FTS 与向量，产品阅读历史、回顾及写入幂等记录保留；恢复产品快照后也会自动重建。索引空间或维度漂移时可停服重建，不需要修改既有迁移。

## 中文混合检索

`POST /api/ext/v1/search` 使用 `notes:read`，例如：

```json
{"query":"如何减少遗忘", "mode":"hybrid", "limit":5, "tags":["学习"], "include_archived":false}
```

`query` 与 `tags` 至少提供一个。查询最多 500 个码点，标签至多 10 项，要求每项标签或其子标签都匹配。`limit` 默认 10、范围 1 至 20，省略或传 0 使用默认值。

关键词采用 FTS5 trigram，中文连续长词拆为重叠三字片段，其他词按字母、数字、下划线和连字符提取。至多取 32 个去重片段，以覆盖数量排序；每路最多召回 200 条。查询中的 FTS 语法字符按普通分隔符处理。单字、双字及短英文使用参数化的字面子串查询，不依赖 trigram 的三字符匹配限制。标签同时参与匹配，父标签过滤包含子标签。

本阶段选择 trigram 是为了无需引入中文词典即可覆盖原文片段和混合语言。与预分词相比，它对长自然语言查询的词义和切词精度较弱，因此需要语义召回补充；一至二字补充路径需要扫描投影。相关正确性由 `TestChineseKeywordShortQueriesAndTagFilters` 验证，真实问题的效果按下文比较三种模式。

语义检索使用同一空间的归一化查询向量，精确计算余弦相似度，低于 0.25 的候选省略。先按归档和标签过滤，再按笔记取最相关分块；混合模式以等权 Reciprocal Rank Fusion 合并关键词与语义排名，常数为 60。同一笔记只返回一次。`score` 是排名信号，`similarity` 仅表示向量相似度，不能作为事实、矛盾或观点变化的证据。

模式行为：

| mode | 行为 |
| --- | --- |
| `hybrid` | 默认；语义关闭、构建未完成或模型故障时使用关键词，并通过 `mode=keyword` 与 `warnings` 告知原因 |
| `keyword` | 仅用中文关键词和标签，无模型请求 |
| `semantic` | 仅用向量，要求非空查询及可用模型与完整索引；失败时返回错误 |

仅按标签查询返回 `mode=keyword`。来源故障不会降级为本地正文输出。命中结果包括新鲜 `note`、`snippet`、`score`、`signals` 及可选的 `similarity`。`snippet.start_rune`、`end_rune` 为原文 Unicode 码点位置，末端不包含，片段至多 240 码点；`source_hash` 对应本次原文版本。正文变化后的旧语义候选不会输出；若仍匹配关键词，混合模式可用新原文返回关键词结果。

## 相关与漫步

`GET /api/ext/v1/notes/{memo_id}/related?limit=5` 使用该笔记全部已索引分块的归一化均值寻找近邻，并对同一顶层标签略加权，不返回自身。要求当前笔记版本已索引，否则返回 `SEARCH_NOT_READY`；空白笔记返回空结果。

`POST /api/ext/v1/discovery/walk` 接收当前资源 `name`、`mode`、已访问资源数组 `path` 和可选的归档开关：

```json
{"name":"memos/current", "mode":"angle", "path":["memos/start","memos/current"]}
```

| mode | 选择方式 |
| --- | --- |
| `continue` | 默认；优先语义近邻，同顶层标签加 0.2 |
| `angle` | 保留语义相关门槛，同话题减 0.3，不同话题加 0.15 |
| `random` | 从当前投影抽样至多 200 条，允许不提供起点，不依赖模型 |

漫步排除当前笔记及路径资源。最近 7 天通过发现打开接口或回顾显式打开的笔记减 0.4；仅被召回、展示、推送或选入回顾不计阅读。无标签时依赖语义和最近阅读，话题变化仅为启发式排名。

响应包含一个 `item`、接下来应原样传回的 `path`、`mode` 与 `exhausted`。路径上限 100，达到上限或候选用尽时 `item=null`、`exhausted=true`；这里的用尽是本次候选范围，不代表所有笔记已读。漫步本身不写产品状态。

`POST /api/ext/v1/discovery/open` 以 `{"name":"memos/id"}` 打开并持久更新最近阅读，使用独立的 `discovery:write` Scope，返回复查后的 `Note`。所有入口的阅读历史共享并纳入备份，点击 Memos 链接不会自动登记。

MCP 提供只读的 `semantic_search`、`get_related_memos`、`semantic_walk`，以及标记会改变状态的 `open_discovery_memo`。参数及 Scope 与 REST 一致。飞书命令和路径传递见[飞书入口](FEISHU.md#交互)。

## 资源与本地验收

模型并发固定为 1，检索与漫步合计并发最多 2，超过返回 429 `SEARCH_BUSY`；请求内部最长 90 秒。矩阵仅在向量修订变化时重载，不为每次查询复制整个矩阵。每个启用空间限制 96 MiB 裸向量及 `max_chunks`；超限记录 `EMBEDDING_CAPACITY`，不发布部分新空间。10000 × 1024 维的裸向量约为 39.1 MiB，构建和缓存替换时仍需额外内存。

自动化验证包括真实 Memos、可控的 Embeddings HTTP 服务、三种模式、来源隔离、删除与归档、模型切换、重启和备份恢复。可控向量用于验证协议及业务正确性，不代表真实模型质量。开发环境的基准数据记录在[开发指南](DEVELOPMENT.md#检索验证)。

以下验收需要实际数据与渠道：

1. 配置真实 embedding 提供商，检查首次索引最终为 `active` 且 `pending_memos=0`，记录耗时、内存峰值、CPU、请求数及费用。检查长笔记、单字与双字、标签和归档。
2. 准备约 20 个你真实会问的问题，按原文人工标出期望资源。保存为 `.local/search-questions.json`，格式为 `[{"query":"真实问题","expected":["memos/期望资源"],"tags":[]}]`。既包含关键词命中，也包含换一种说法、长笔记和短查询。
3. 执行下列脚本，比较 `keyword`、`semantic` 和 `hybrid` 的 Hit@5、MRR@5、中位延迟和 P95。没有填写期望资源的问题只记录结果，不计命中率；模型错误或降级使脚本非零退出。输出文件不覆盖已有报告，不保存正文或凭据。

```bash
python3 scripts/evaluate-search.py --questions .local/search-questions.json
```

4. 从数条不同主题的笔记检查相关结果和三种漫步模式，传回路径并显式打开，检查重复排除和最近阅读降权。在真实飞书应用中验证搜索、相关、漫步、路径传递及查看；验证其他发送者不能访问。
5. 结合实际笔记数、分块数、维度、机器配置和来源网络延迟复测资源占用，必要时降低 `max_chunks`、`batch_size` 或采用更小维度。云端合成基准不能替代部署机上的端到端测量。
