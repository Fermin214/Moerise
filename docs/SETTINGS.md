# Moerise 系统设置与动态凭据管理

[English](SETTINGS.en.md)

Moerise 采用分层配置与版本化持久设置架构：底层基础设施参数由部署环境管理，而日常偏好与模型凭据可在 Web 界面动态调整并加密持久化。

---

## 一、配置分层与优先级

1. **部署环境配置（基础设施）**：
   - 包括 Memos 根地址、绑定作者账号、Memos PAT、对外公开域名（Core 使用 `MOERISE_PUBLIC_ORIGIN`，Web 使用 `PUBLIC_ORIGIN`）、监听端口、数据目录以及状态加密主密钥（`MOERISE_STATE_ENCRYPTION_KEY`）。
   - 通过 `.env` 环境变量或 `config.json` 传入，供 Core 启动时加载。
2. **产品持久设置（日常偏好与凭据）**：
   - 包括时区、每日回顾频率与时段、模型提供商与 API Key、飞书/Telegram 渠道凭据及自定义 AI 提示词。
   - 首次启动时从部署配置初始化并存入 `state.sqlite3`；后续以已保存设置为准。模型、渠道和提示词保存后热生效；时区、回顾规则和推送时段从下一个当地日生效，当天已固定计划保持原规则。重启服务或重建索引均不丢失设置。

---

## 二、敏感凭据加密机制

所有模型 API Key、机器人 Token 及 Webhook 密钥均在服务端使用 AES-256-GCM 算法加密存储：
- 加密密钥由部署环境变量 `MOERISE_STATE_ENCRYPTION_KEY` 派生；
- 接口返回设置时不回传敏感密钥原文，仅返回布尔状态 `configured`；
- 备份数据库时必须同步保管好状态加密主密钥，否则无法解密凭据。

---

## 三、设置更新与热生效协议

### 1. 读取设置
- 请求：`GET /api/app/v1/settings`
- 返回内容包含设置版本号 `version`、各项配置对象、凭据状态及渠道能力矩阵（是否支持发送文字、图片、是否支持私聊速记）。

### 2. 增量更新设置
- 请求：`PATCH /api/app/v1/settings`
- 携带读取到的版本号 `version`、需要修改的字段以及密钥操作动作。
- **密钥操作指令**：
  - `{"action":"keep"}`：保持原密钥；
  - `{"action":"replace","value":"新密钥"}`：替换密钥；
  - `{"action":"clear"}`：清空密钥。
- **版本并发控制**：提交的版本号若落后于服务端版本，接口返回 409 `SETTINGS_CONFLICT`，防止多端修改相互覆盖。

### 3. 热生效与资源排空 (Drain)
- 保存新设置时，服务端最多等待 5 秒排空使用旧设置的操作，然后替换受影响的模型与渠道客户端；超时返回可重试的 `SETTINGS_BUSY`，旧设置继续有效。
- 修改大语言模型（LLM）配置无需重建向量索引；修改向量模型（Embedding）则会触发新空间代次的索引构建。
