# Android 安装与升级

Moerise Android 0.1.0 支持 Android 8.0（API 26）及以上系统，发行 APK 包含
`arm64-v8a` 和 `x86_64`。服务地址使用 Moerise 对外 Web 的 HTTPS 入口，只填写协议、
主机和可选端口。

## 安装

0.1.0 是首次发行，以新安装数据和完整的 Room schema 1 建库。
开发期 APK 与数据库不提供兼容迁移，首次安装不需要执行旧开发版升级流程。

从发行附件下载 `moerise-android-v0.1.0.apk` 及同名 `.sha256` 文件。
核对 SHA-256 后，通过文件管理器安装；系统提示时为文件管理器开启安装应用权限。
ADB 安装命令：

```bash
adb install moerise-android-v0.1.0.apk
```

首次启动填写服务地址和 Moerise 用户名、密码。登录后可直接在主页写作。
点击保存后，笔记先进入本机队列，输入框清空。离线保存的笔记会出现在时间线，
恢复连接后自动上传。未点击保存的输入会在本机恢复，不会自动上传。
主页通过同步图标显示连接与队列状态，点击图标可立即同步。

笔记的阅读、编辑、归档与删除都在主页完成，三点菜单提供对应操作。
卡片正文和时间戳不会进入独立页面，回顾、漫步、洞察和观星中的来源阅读会回主页定位笔记。
同一时间只编辑一条笔记：编辑已有笔记时暂时隐藏顶部新建输入，
切换编辑目标先保存前一条的本机输入；保存或取消编辑后恢复顶部未完成内容。
未点击保存的输入仅存于本机，重新编辑可继续恢复。

`-unsigned.apk` 用于构建检查，需要发行签名后才能安装。
`.fixture` 与 `.benchmark` 包分别用于隔离服务流程和性能测量。

开发包名为 `io.github.fermin214.moerise.dev`，桌面名称为 Moerise Dev。开发包与
发行包各自保存登录状态和本机草稿；切换到发行包前，将需要保留的草稿提交到 Core。

## 后续正式版本升级

已有正式发行版本时，使用相同包名、相同签名且更高 `versionCode` 的发行 APK 覆盖安装。
以下参数替换为后续发行附件的实际路径：

```bash
adb install -r "/绝对路径/后续版本发行包.apk"
```

覆盖安装保留应用数据；不要先卸载。首次发行的 `versionCode` 为 1，后续发行必须递增。
签名身份发生变化时，Android 会拒绝覆盖安装。调试签名安装也应通过独立包进行测试，
避免与正式发行身份混用。

正式发行后数据库结构变化时，递增 Room 版本并提供迁移。
升级后检查主页未完成输入、时间线中的离线笔记、保存结果不明的请求、登录状态和语言选择。
队列重试沿用持久记录的请求；遇到来源冲突时先合并，或另存为新笔记。

本机数据库、凭据和附件排除云备份及设备迁移。卸载应用或在系统设置中清除数据会删除
本机草稿。应用设置中的“删除本机账号数据”只删除选中账号的本机内容，并退出登录。
服务器中的笔记通过 Core 和 Memos 保存。

## 发行附件

发行归档包括 APK、SHA-256、构建信息 JSON、本安装说明、第三方许可与声明。
R8 `mapping.txt` 用于定位发行崩溃，应随构建私有保存。

Windows 发行构建通过仓库公共设备锁执行，源码仓库入口见 `docs/ANDROID.md` 的
“Windows 发行入口”和 `docs/android/DEVICE-CHECKS.md` 的“Windows 集中入口”。
`release.ps1 sign -SigningFile <绝对路径>` 读取 `keystore`、`alias`、
`store_password`、`key_password`，密码只通过子进程环境传给签名工具。
首次发行使用默认 `-VersionCode 1`；后续正式版本设置比已发行版本更高的值，
例如 `-VersionCode 2`。签名材料与 TLS 私钥放在仓库外。
构建日志与校验结果一并保存在发行归档中。
