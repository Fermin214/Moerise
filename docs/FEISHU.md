# 飞书入口

飞书应用机器人通过 HTTP 事件回调接收绑定账号的单聊消息，调用记录与回顾业务服务，再回复原消息。笔记正文和附件保存在 Memos，回顾批次与 REST、MCP 共用。

## 应用与配置

在飞书开放平台创建企业自建应用并启用机器人，开放接收用户单聊消息、机器人发送消息和读取消息资源文件所需的应用权限。发布应用版本，将使用者加入应用可用范围。事件订阅选择 HTTP 回调并订阅 `im.message.receive_v1`。

配置 `channel`：

| 字段 | 用途 |
| --- | --- |
| `kind` | `feishu-app` |
| `app_id`、`app_secret` | 应用凭据，服务端换取并缓存租户访问令牌 |
| `verification_token` | 事件订阅的 Verification Token，至少 16 字符 |
| `encrypt_key` | 事件订阅的 Encrypt Key；配置后只接收加密事件并检查消息签名 |
| `user_open_id` | 唯一允许交互的使用者 Open ID，形如 `ou_...` |
| `destination` | 应用机器人推送目标；填写时必须与 `user_open_id` 相同 |

四项应用凭据与身份字段须一起填写；全部留空时关闭应用机器人入口。`app_secret` 至少 16 字符，相关配置仅保存在服务端。回调地址为部署的 HTTPS 根地址加 `/hooks/feishu`。使用者 Open ID 取自该应用下的身份，不能用手机号、Union ID 或其他应用的 Open ID 替代。

服务先检查 Verification Token、应用标识、发送者和单聊类型；配置 Encrypt Key 时，额外验证 `X-Lark-*` 签名并解密事件。URL 验证回显经过 Token 校验的 `challenge`。其他发送者、机器人消息和群聊事件直接应答，不读写 Memos，也不发送私人内容。

参考：[接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)、[获取消息资源](https://open.feishu.cn/document/server-docs/im-v1/message-resource/get)。事件加密与签名按[官方 Go SDK](https://github.com/larksuite/oapi-sdk-go/tree/v3.12.2/event)的协议适配。

## 交互

| 消息 | 操作 |
| --- | --- |
| `记录 正文` | 创建私有笔记，正文内的 `#标签` 由 Memos 解析 |
| 图片或文件消息 | 下载原消息资源并保存为附件笔记，单文件至多 8 MiB |
| `查看 memos/资源标识` | 复查并返回该笔记原文摘要及链接 |
| `回顾` | 获取或创建固定当日批次 |
| `换一组` | 创建后续批次，事件重投复用同一换组键 |
| `打开 批次标识 memos/资源标识` | 保存打开时间 |
| `略过 批次标识 memos/资源标识` | 保存略过时间 |
| 其他消息 | 返回操作说明 |

普通文本须有 `记录` 前缀才保存。图片和文件消息本身表示保存附件。保存结果返回 Memos 资源名及原文链接；查询与回顾回复前复查来源身份和正文。来源故障时等待重试，不使用旧正文。

## 事件与恢复

回调先将事件持久入队再应答，后台工作循环执行耗时操作。按消息标识去重并保存事件标识及摘要，同一消息的正文变化返回冲突。记录幂等键由消息标识生成；换组、打开和略过调用共享回顾服务。

待处理消息使用 AES-GCM 加密暂存，密钥由应用 Secret 派生，密文绑定来源实例、作者及消息标识。业务完成后删除消息密文，只保留操作结果引用、状态、回复 UUID 和平台回执。备份配置时保留应用 Secret；Secret 变化后，旧密文需要原 Secret 才能继续处理。更换绑定使用者或应用后，旧身份的事件不进入发送流程。

记录和附件资源标识由独立分页密钥、来源绑定及幂等键派生后持久保存，旧记录沿用已有标识。配置保持一致时，恢复业务执行前的事件快照也能先复查原资源，避免另建笔记或附件。更换分页密钥后，数据库中已有标识继续有效；恢复旧快照前须恢复配套配置，并核实快照之后的来源操作。

回复使用持久 UUID，并保存平台消息标识。请求已发出但未收到可信回执时，保留 `unknown` 状态，暂停该回复的自动重发；笔记写入与回复状态分别保存。服务重启将中断的业务处理恢复为等待状态，已完成业务不会因回复故障重复保存。事件队列随产品状态一起备份，索引重建不会删除事件。
