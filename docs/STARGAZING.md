# 观星

观星将有文本向量的真实笔记呈现为星体，用语义邻近关系组织星群。笔记原文、标签与附件由 Memos 保存，点星后通过已有笔记接口读取最新内容。

## 布局与语义

默认算法为 `umap-balanced-v1`，使用聚合后的笔记向量：

| 参数 | 值 |
| --- | --- |
| `n_neighbors` | 15 |
| `min_dist` | 0.12 |
| `spread` | 1.0 |
| `metric` | cosine |
| `random_state` / `transform_seed` | 42 |
| `n_jobs` | 1 |

各文本块先归一化，按内容摘要去重后等权聚合，再归一化为笔记向量。布局不调用 Embedding 或聊天模型，支持不同维度的已发布向量空间。少于 12 条笔记或全部向量相同时使用 PCA；单条笔记居中。

主题识别独立于展示坐标：10 维 UMAP 配合 HDBSCAN，使用原向量中心亲和度与近邻支持过滤分组。标签与关键词生成主题名称，允许笔记独立存在。星体尺寸和亮度由资源名种子、语义中心性、邻近密度和独特性共同确定。重合星点按资源名做小幅、可复现的避让，增量更新固定已发布点位；零方差布局使用备用归一化尺度，避免新增笔记落到极远处。

## 快照与增量

Core 在向量索引就绪后调度布局，普通变化按一分钟间隔合并。计算期间继续提供已发布快照，不占用同步或向量构建的后台名额。

「设置 → 通用 → 启用观星」控制独立的 `stargazing.enabled`，默认开启。关闭后隐藏入口，停止提交与重试布局任务；已经开始的计算可以结束，但结果不会发布，即使计算期间重新开启也不会接收旧任务结果。向量索引、星图快照与模型均保留，语义检索和漫步继续使用 Embedding。重新开启时读取已有快照，再处理索引变化。

首次生成持久化 UMAP 模型及坐标归一化基准。相同向量空间内，新增和向量变化的笔记通过 `transform` 定位，未变笔记的坐标与星体属性直接复用；删除的笔记从快照移除。小语料生成的 PCA 模型也延续该框架，主动重新生成后才按语料规模选择 UMAP。已有主题 ID 与名称在增量更新中保持稳定，新笔记根据原向量亲和度及近邻支持分配。

“重新生成星图”建立新的坐标框架，同时重新识别主题。更换 Embedding 模型空间也会建立新框架。模型文件丢失时，布局服务重新拟合；原有已发布快照仍可读取。

`index.sqlite3` 的 `star_snapshots` 保存点位、主题、关联和向量修订，`star_heads` 原子切换活跃版本。发布前核验来源配置、向量代次、投影修订、父版本与重建请求，防止过期计算覆盖新数据。每位作者保留最近两份快照；布局服务在每个语义空间保留最近使用的三份模型。

旧 PCA 快照可作为迁移期间的读取结果，均衡 UMAP 完成后自动切换。没有文本向量的笔记通过“未定位笔记”列表读取，不生成星体。

## 渲染与交互

Canvas 绘制全部语义星体；星点小光晕、局部密度柔光和极淡背景雾分层处理，辉光由真实点位密度生成。艺术星图与摄影氛围共用坐标和星体属性。

平移、缩放和主题聚焦在浏览器完成，只在交互或数据变化时绘制，不运行持续动画。远景呈现主题与整体密度，中景展开子主题，近景按需读取少量摘要；点星打开实时原文。支持键盘操作、手机触摸、主体与全图取景及全屏。

## 服务与部署

`services/layout/` 是独立 Python 布局服务，Compose 使用内部地址 `http://layout:8766`，不发布外部端口。Core 通过 `MOERISE_LAYOUT_URL` 配置地址，原生部署默认 `http://127.0.0.1:8766`。

Compose 通过 `stargazing` profile 启动布局服务，`.env.example` 默认包含 `COMPOSE_PROFILES=memos,stargazing`。不使用观星时，关闭应用开关，移除该 profile，并执行 `docker compose stop layout`。应用开关不控制 Docker；仅移除 profile 也不会停止已运行容器。恢复时加回 profile、运行 `docker compose up -d`，再开启应用开关。

HTTP 父进程只使用标准库；每次布局启动独立科学计算子进程，完成后退出以释放内存。单服务同一时间只执行一个布局任务。Compose 默认限制 1 核 CPU、1 GiB 内存，通过 `LAYOUT_CPU_LIMIT` 与 `LAYOUT_MEMORY_LIMIT` 调整。

模型和 Numba 缓存在独立 `layout-data` 卷中，不包含产品状态。该卷可重建；保留它有助于延续增量坐标框架。部署和原生启动命令见[运行指南](OPERATIONS.md)。

## 接口

- `GET /api/app/v1/map`：读取快照，包含 `points`、`topics`、`links` 和 `layout_frame`。语义点包含 `stellar.seed`、`role`、`radius`、`luminosity`。更新期间可附带 `update_state: building` 或 `unavailable`。
- `POST /api/app/v1/map/rebuild`：提交重建请求，返回 `202 {"status":"queued"}`。使用本人会话、同源与 CSRF 校验，不修改笔记原文。

关闭观星后，读取返回 `status: disabled`、`disabled_reason: stargazing` 和空点集；重建返回 `409 STARGAZING_DISABLED`。Embedding 关闭时，读取的 `disabled_reason` 为 `embedding`。

浏览器仅接收布局结果，不接收原始向量。首次向量或布局尚未就绪时通过状态字段提示；服务故障后自动重试。
