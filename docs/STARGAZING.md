# 观星

观星将有文本向量的真实笔记呈现为星体，用语义邻近关系组织星群。笔记原文、标签与附件由 Memos 保存，点位直接携带摘要 `excerpt` 与创建时间 `create_time` 用于悬停与近景预览，点星后优先读取本地索引并在需要时请求实时原文。

## 布局与语义

默认算法为 `umap-balanced-v1`，使用聚合后的笔记向量：

| 参数 | 值 |
| --- | --- |
| `n_neighbors` | 15 |
| `min_dist` | 0.12 |
| `spread` | 1.0 |
| `metric` | cosine |
| `random_state` / `transform_seed` | 42 |
| `n_jobs` | 1 |

各文本块先归一化，按内容摘要去重后等权聚合，再归一化为笔记向量。布局直接复用不同维度的已发布向量空间。少于 12 条笔记或全部向量相同时使用 PCA；单条笔记居中。

主题识别独立于展示坐标：10 维 UMAP 配合 HDBSCAN，使用原向量中心亲和度与近邻支持过滤分组。关键词提取结合 c-TF-IDF 与父级主题高频词抑制生成主题与子主题名称。旧快照首次增量更新时按关键词刷新名称，保留既有布局中的分组和未变化的点位。星体尺寸和亮度由资源名种子、语义中心性、邻近密度和独特性共同确定。重合星点按资源名做小幅、可复现的避让，增量更新固定已发布点位；零方差布局使用备用归一化尺度，避免新增笔记落到极远处。

## 快照与增量

Core 在向量索引就绪时调度初次布局，并在每天服务时区 `03:00` 检查索引与模型变更按需调度增量或重建任务，同时支持随时点击“重新生成星图”主动触发。计算期间继续提供已发布快照，不占用同步或向量构建的后台名额。

「设置 → 通用 → 启用观星」控制独立的 `stargazing.enabled`。新实例默认关闭，升级保留原有选择。关闭后隐藏入口，停止提交与重试布局任务；已经开始的计算可以结束，但结果不会发布，即使计算期间重新开启也不会接收旧任务结果。向量索引、星图快照与模型均保留，语义检索和漫步继续使用 Embedding。重新开启时读取已有快照，再处理索引变化。

首次生成持久化 UMAP 模型及坐标归一化基准。相同向量空间内，新增和向量变化的笔记通过 `transform` 定位，未变笔记的坐标与星体属性直接复用；删除的笔记从快照移除。已有主题 ID 与名称在增量更新中保持稳定，新笔记根据原向量亲和度及近邻支持分配。

“重新生成星图”建立新的坐标框架，同时重新识别主题。更换 Embedding 模型空间也会建立新框架。模型文件丢失时，布局服务重新拟合；原有已发布快照仍可读取。

`index.sqlite3` 的 `star_snapshots` 保存点位、主题、关联和向量修订，`star_heads` 原子切换活跃版本。发布前核验来源配置、向量代次、投影修订、父版本与重建请求，防止过期计算覆盖新数据。每位作者保留最近两份快照；布局服务在每个语义空间保留最近使用的三份模型。

均衡 UMAP 布局完成后即可浏览；旧快照若非 `umap-balanced-v1`，会在服务端自动过滤并等待重算，客户端不再兼容渲染旧布局。没有文本向量的笔记通过“未定位笔记”列表读取，不生成星体。

## 渲染与交互

Canvas 按真实点位密度绘制星体和辉光。

平移、缩放和主题聚焦只在交互或数据变化时重绘。远景呈现主题与整体密度，中景展开子主题，近景与悬停直接渲染快照点位携带的 `excerpt` 摘要，无需批量拉取详情。点星或选择未定位笔记会在图内打开原文阅读卡，工具栏提供全图取景、重新生成星图和全屏。浏览与重试均只读取快照。

## 服务与部署

`services/layout/` 是独立 Python 布局服务，Compose 使用内部地址 `http://layout:8766`，不发布外部端口。Core 通过 `MOERISE_LAYOUT_URL` 配置地址，原生部署默认 `http://127.0.0.1:8766`。

新装只启动 Memos 与 Core。要使用观星，先在 `.env` 的 `COMPOSE_PROFILES` 追加 `,stargazing`（外接 Memos 时设为 `stargazing`），再执行：

```bash
docker compose pull layout
docker compose up -d layout
```

在「设置 → AI」配置 Embedding 向量模型，再在「设置 → 通用」打开「启用观星」。Core 在后台探测布局服务，停机或版本不兼容时保留已发布星图并显示对应提示。升级时按[升级与回滚](OPERATIONS.md#五升级与回滚)同步更新并重启 Core 和布局服务。

停用时先关闭应用开关，执行 `docker compose stop layout`，再移除 profile。应用开关只控制 Core 的布局调度。

HTTP 父进程只使用标准库；每次布局启动独立科学计算子进程，完成后退出以释放内存。单服务同一时间只执行一个布局任务。Compose 默认限制 1 核 CPU、1 GiB 内存，通过 `LAYOUT_CPU_LIMIT` 与 `LAYOUT_MEMORY_LIMIT` 调整。

模型和 Numba 缓存在独立 `layout-data` 卷中，不包含产品状态。该卷可重建；保留它有助于延续增量坐标框架。部署和原生启动命令见[运行指南](OPERATIONS.md)。

## 接口

- `GET /api/app/v1/map`：读取快照，包含 `points`（附带 `excerpt` 与 `create_time`）、`topics`、`links` 和 `layout_frame`。语义点包含 `stellar.seed`、`role`、`radius`、`luminosity`。更新期间可附带 `update_state: building` 或 `unavailable`。
- `POST /api/app/v1/map/rebuild`：提交重建请求，返回 `202 {"status":"queued"}`。使用本人会话、同源与 CSRF 校验，不修改笔记原文。

关闭观星后，读取返回 `status: disabled`、`disabled_reason: stargazing` 和空点集；重建返回 `409 STARGAZING_DISABLED`。Embedding 关闭时，读取的 `disabled_reason` 为 `embedding`。

浏览器仅接收布局结果，不接收原始向量。首次向量或布局尚未就绪时通过状态字段提示；服务故障后自动重试。
