# AI 效果与工程验证

2026 年 10 月 27 日的评测采用 34 条虚构中文笔记和 40 个固定案例，覆盖单条洞察、多条比较、普通问答、主题时间线和证据不足。运行环境为 Go 1.27.3、Linux amd64、Memos 0.31.0。真实生成通过标准 OpenAI Chat Completions 调用 `workbuddy/deepseek-v4.1-flash`；Magpie 仅提供测试路由，业务代码使用独立的 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 适配器。

## 数据与判定

[固定数据集](../tests/testdata/stage4-cases.json)包含 2023 至 2026 年的工程与园艺笔记，其中两条归档。每类八例，逐例固定问题、筛选条件、期望来源、关键要点、禁止的推断及核对事项。笔记包含同文副本、矛盾记录、误导指令、计划与实测区分、三种日期和超出上下文预算的长文。

| 数据修订 | SHA-256 | 差异 |
| --- | --- | --- |
| `720b3c4` | `c17d4c2bcfbc4be239436b5fede84570a6a2a8bd5314b1f412b167ac2ce48fd5` | 首次实调前冻结的 34 条笔记与 40 个案例 |
| `2e02fc6` | `4f1144482bc645bd3b5a07001ee00a606d4f99e6b0ff571cc08a5fb00f7c5d4d` | 只删除八个时间线请求中的 `names`；笔记、问题、筛选、期望和核对项不变 |

时间线调用问答接口，通过问题、标签和日期召回。显式 `names` 属于洞察接口；首次八个时间线请求被接口以 422 拒绝，均在模型调用前结束。数据的 schema version 仍为 1。

引用检查覆盖来源身份、状态、标签、日期、版本摘要、UTF-8 字节区间、行号和引用归属；输出中的实际来源与 `used_sources` 必须一致。流式结果须有合法完成事件，错误和部分输出不能计作完整成功。

内容核对以原文及逐例评分项为依据，分别记录 `correct`、`omission`、`wrong_citation` 和 `unsupported`。来源位置校验通过后仍需检查措辞是否与原文一致，例如“未记录”与“未发生”、事件日期与记录日期、同一事件的副本与独立实验。代理审阅与人工评分使用独立字段，字符串匹配和模型自评不计作人工评分。

## 效果结果

40 个案例各有一个完整结果通过引用位置及完成结构检查，输出中不存在虚构证据 ID 或越界来源。Codex 对这些具体生成结果的内容审阅为 36 例正确、2 例遗漏、2 例无依据结论，另有 3 例结果状态与固定期望不同。人工评分字段为 `null`。

| 类别 | 完整结果 | 内容正确 | 遗漏 | 无依据结论 | 状态符合期望 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单条洞察 | 8/8 | 8 | 0 | 0 | 7/8 |
| 多条比较 | 8/8 | 6 | 1 | 1 | 7/8 |
| 普通问答 | 8/8 | 8 | 0 | 0 | 8/8 |
| 主题时间线 | 8/8 | 6 | 1 | 1 | 7/8 |
| 证据不足 | 8/8 | 8 | 0 | 0 | 8/8 |
| 合计 | 40/40 | 36 | 2 | 2 | 37/40 |

[逐例报告](evidence/stage4-live.json)保存问题、期望、全部尝试、选定结果、引用位置、模型用量与审阅依据。每条审阅通过原报告文件名和完整结果 SHA-256 绑定具体输出；旧生成的评价继续保存在历史中。

四个内容问题分别为：

- `multi-cache-observations` 遗漏不能排除跨年软件环境差异、缺少重复轮次等具体限制，仅笼统指出比较受限。
- `multi-basil-confounded-observations` 声称 2025 年比 2024 年“更依赖表土检查”；2024 年已按表土干燥程度浇水，原文没有提供可比较的依赖程度。
- `timeline-cache-four-years` 将同一笔记中的提案与试验说成创建时间各不相同，并遗漏后续编辑只修正文字、没有追加试验的说明。
- `timeline-duplicate-event-date` 只排列两份 M1 笔记的创建时间，遗漏 M2 的创建时间及完整记录顺序。

三个状态差异均为期望 `answered`、实际 `insufficient`：迷迭香单条洞察将未知移栽结果列为缺口，QB17 比较将核定唯一结果所需的原始日志列为缺口，回填时间线将自然空缺的 2024 年列为缺口。这些答复已经陈述对应的已知事实与边界，状态差异单独保留。

比较提示要求减少扩写、区分未记录与未发生、保留正文事件日期并通过 `citations` 表达引用。16 个比较及时间线结果中仍有 9 例输出超过一条解释，2 例在正文中重复证据编号。业务解析器检查条目结构、引用和完成条件；提示遵循程度与内容正确性分别记录。

## 失败与复测

| 执行组 | 业务尝试数 | 完整结果 | 失败或修正 |
| --- | ---: | ---: | --- |
| 首次固定案例 | 40 | 31 | 八个时间线因 `names` 契约错误被拒绝；一例多条比较因 `INVALID_CITATION` 中断 |
| 引用提示与契约修正后的比较及时间线 | 16 | 15 | 回填时间线在五条内容后返回 `LLM_PROTOCOL`，无完成事件 |
| 录制代理的首次诊断 | 1 | 0 | 沙箱连接被拒绝，没有取得上游响应，业务返回 `LLM_UNAVAILABLE` |
| Linux 同容器录制诊断 | 1 | 1 | 上游只有一次请求，SSE、结果记录、`stop` 与 `[DONE]` 均合法 |
| 事实、事件日期与缺失信息提示补强后的比较及时间线 | 16 | 16 | 完成结构和来源位置均通过；内容差异按上表记录 |

共 74 次业务尝试，其中 63 次完整完成、8 次契约拒绝、3 次故障中断；另外七次并发测量全部完成。选定结果使用最后一个完整有效生成，历史失败及后续失败均独立保存。汇总中的 `complete` 只表达完整执行覆盖，内容评分与人工评分分别保存。

首次生成实现对应 `720b3c4`，引用规则及 Anthropic 用量修正对应 `a99c092`，事实与日期提示补强对应 `bb204bd`。单条洞察、普通问答、证据不足和单条并发测量的提示及模型调用保持一致，其 24 个案例和七次并发证据直接复用。

内容审阅推动了两次比较提示修改：先明确所有跨笔记解释至少引用两条不同笔记，区分正文副本与来源版本、不同实验批次；再明确缺失记录、事件身份、日期与局限，减少额外解释。修正后复测受影响的全部 16 个比较及时间线案例，固定问题与期望保持一致。

原始 `LLM_PROTOCOL` 请求缺少供应商原始帧，无法确定具体违例字段。独立录制诊断取得 188 个合法 SSE data 帧及 54408 字节响应体，末行结果为 `answered` 且 `missing=[]`，业务返回三个事实和完成事件。该故障的原始业务事件与诊断结果分别保存。

真实 Memos 的两个 AI 流程分别验证同一选定来源跨 REST、MCP 和飞书的证据与结果映射，以及已完成生成的重投、Store 重开、索引重建、在线备份和快照恢复。Scope 同时要求 AI 与笔记读取权限；发送前来源修改后只发送固定提示。来源修改、删除、作者越界、来源不可用、客户端取消、模型超时、限流、无效返回和流中断由可控模型及来源专项覆盖。

## 复现

先按 [AI 配置](AI.md)填写 `llm`，再在 Linux 环境中执行：

```bash
MOERISE_STAGE4_CONFIG="$PWD/.local/config.json" \
MOERISE_STAGE4_OUTPUT="$PWD/.local/stage4-live.json" \
MOERISE_STAGE4_CONCURRENCY=true \
go test -tags=integration ./tests -run '^TestStage4LiveAcceptance$' -v -count=1 -timeout=30m
```

执行器只采用配置中的 LLM，自动创建独立 Memos、账号、产品状态、索引和服务进程。笔记通过官方 API 导入并读回核对；Memos 正文限制设为 256 KiB，以容纳长笔记。运行需要 Docker Engine、Docker CLI 与模型连接。

`MOERISE_STAGE4_CASES` 可筛选逗号分隔的案例 ID。只复测某个案例时，将 `MOERISE_STAGE4_CONCURRENCY=false`，并指定新的报告文件。逐例原子保存的 JSON 包含请求、完整 SSE、业务结果、引用、预期、延迟、用量和进程资源；报告拒绝覆盖已有文件。测试流程和完整集成命令见[开发指南](DEVELOPMENT.md#ai-评测)。

## 飞书平台检查

使用连接开发 Memos 的应用机器人，配置绑定身份与 LLM。先发送两条虚构笔记：

```text
记录 #AI联调 第一组虚构实验做100次读取，12次超时；没有P95记录。
记录 #AI联调 第二组虚构实验做100次读取，2次超时；条件与第一组不同，不能据此认定改善原因。
```

将创建回复中的资源名分别用于单条及多条 `洞察` 命令，再发送：

```text
问答 两组各做了多少次读取、超时多少次？ #AI联调
问答 两组实验的P95分别是多少？ #AI联调
历程 虚构实验的记录 #AI联调
```

核对事实、解释、缺失信息、原文链接及时间段；确认 P95 问题明确返回缺少记录。记录入站消息、各回复的平台消息标识及分片编号，并与持久队列回执对应。普通聊天返回命令说明；以 `记录` 为前缀的文本保存为原文。长结果分片、事件重投、来源变化、重启与恢复的控制流程采用隔离集成测试复现。
