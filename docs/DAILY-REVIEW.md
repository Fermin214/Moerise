# 每日回顾

每日回顾的产品规则见 [PRD 第三章](PRD.md#1-每日回顾-daily-review)。Core 每天生成固定的全天计划，Web 展示全部条目，飞书按互不重复的时段分配推送；机器 REST 与外部 MCP 只读取已有结果。

飞书每次推送先单独发送一条 `「今日回顾」`，整次只发一次。随后逐篇发送完整正文、原图，最后发送 `#标签  创建于YYYY-MM-DD`；无标签时只发 `创建于YYYY-MM-DD`。日期取来源 `create_time`，按配置 `timezone` 换算。不附加链接、片号或状态提示，普通文件不推送。没有可发送正文或图片的笔记不发尾注，整次均无内容时也不发标题。

## 选择规则

`review` 控制候选范围与每次数量：

| 字段 | 默认值 | 约束与含义 |
| --- | --- | --- |
| `count` | 3 | 每个推送时段的条数，允许 1 至 20 条 |
| `min_age_hours` | 72 | 笔记创建后的等待小时数，0 至 87600 |
| `recent_days` | 7 | 排除最近若干当地日内已选中的笔记，0 至 3650；0 表示关闭近期排除 |
| `include_archived` | false | 是否将归档笔记纳入候选 |

先按作者、等待期、近期历史、归档开关和可阅读内容过滤，再等概率打乱候选顺序并抽取。同一主题的多条笔记可以同时出现。有正文或图片的笔记可以入池；只有 PDF、压缩包等普通文件而无正文或图片的笔记不占名额。

全天选取数量为时段数乘以 `count`。例如 `09:00`、`18:00` 各 3 条，全天选择 6 条，前 3 条分配给上午，后 3 条分配给晚上。候选不足时按时段先后填充，最后一个有内容的时段可以不足额，后续时段为空；候选为空时固定空结果，不推送。

近期排除按配置时区的日期计算，例如 7 天包含选取当天及前 6 天。计划、分配和选入历史在同一事务中保存，未读或未送达的笔记也进入近期排除。等待期按实际经过的小时计算。

选中前向 Memos 复查原文，过滤已删除、作者不符、状态不符或未到等待期的笔记。来源故障返回错误，由后台重试；空候选才生成空批次。首次全量同步完成后才生成回顾。

## 固定计划与读取

后台按配置时区每天生成回顾，关闭通知后也会生成。本人客户端的 `GET /api/app/v1/reviews/daily` 使用同一生成服务，全天返回全部条目，不按推送时段分组。机器 REST 与外部 MCP 在计划生成前返回 `REVIEW_NOT_FOUND`，读取不会创建计划。

计划冻结生成时的时区、设置版本、规则和时段。修改数量、等待期、排除期、归档开关或时段不会修改当天计划；新规则从后续日期使用。重启、刷新及切换入口不重新抽样，空结果同样固定。同一作者的同一当地日期只发布一个计划，切换时区不会为已存在的日期另选一组。

Web 完整显示正文与图片，并可进入笔记详情查看全部附件。阅读、打开和略过不改变计划，不登记阅读历史；界面没有换组、未读数或完成动作。

每个条目保存资源名、选中时的来源摘要与选中时间。历史批次的打开、略过记录继续保存；发送记录由通知队列独立管理。

读取已有批次时再次验证来源身份，逐条获取最新原文。已删除或不再属于绑定作者的资源保留历史位置，以 `unavailable: true` 标记，省略正文，不填入新笔记。来源不可用或身份检查失败时，整个请求返回错误。

## 配置与恢复

省略时长字段时使用 72 小时和 7 天，显式填写时使用配置值。`topic_limit` 不参与选择，无需配置。调整规则不会重新生成当天结果。

重启后直接读取已有计划。索引重建不删除计划、分配或回顾历史；重建期间已有计划仍按资源名复查来源。在线产品状态快照包含这些记录，恢复后沿用标识和条目状态。

升级时将当天最新的历史批次接入固定计划，不扩充或重新选取。已经入队的历史通知继续引用原批次并恢复整批发送，尚未入队的时段不重复分配该批次。历史换组幂等键可重放已有结果，新换组请求返回 `REVIEW_REPLACEMENT_DISABLED`。推送次数、最近一次补发及发送恢复见[调度与发送队列](NOTIFICATIONS.md)，接口见 [API v1](API-V1.md#每日回顾与-mcp)。
