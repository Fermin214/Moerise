# Moerise 每日回顾

[English](DAILY-REVIEW.en.md)

每日回顾（Daily Review）旨在让用户过去写下的思考、灵感摘录与日常速记自然地重新浮现，帮助发现曾经关注的问题与不同时期思想之间的潜在联系。

---

## 一、核心设计哲学：无压力重温

传统的打卡或复习软件往往带有“未读计数”、“待办列表”或“坚持天数”等指标，容易给用户造成心理负担与任务压力。Moerise 每日回顾遵循**绝对无压力原则**：
- **不设待办红点**：没有“今日未读”数字角标。
- **无需标记完成**：读过、略过或仅仅瞥一眼均无需点击任何确认按钮，没有任何“打卡中断”的负罪感。
- **静态固定呈现**：每天生成一份确定的全天回顾清单，无论在 Web 还是消息渠道，随时可读，不随刷新而突变。

---

## 二、候选选取与去重规则

每日回顾引擎依据以下配置参数进行候选池筛选与随机抽取：

| 参数 | 默认值 | 允许范围 | 功能说明 |
| --- | --- | --- | --- |
| `count` | `3` | 1 至 20 | 每个推送时段抽取的笔记条数。 |
| `min_age_hours` | `72` | 0 至 87600 | 笔记创建后的冷却成熟期（小时）。新笔记需沉淀一段时间才进入候选。 |
| `recent_days` | `7` | 0 至 3650 | 近期排除天数。排除最近若干当地日内已选入回顾的笔记，防止频繁重复。 |
| `include_archived` | `false` | true / false | 是否将已归档的旧笔记纳入回顾候选池。 |

### 选取流程
1. **基础过滤**：筛选出属于绑定作者、创建时间已超过 `min_age_hours`、且在过去 `recent_days` 内未被选中的笔记。
2. **内容有效性检查**：笔记必须包含文字正文或图片附件。仅含 PDF、ZIP 等附件而无任何文字与图片的笔记不占用回顾名额。
3. **等概率抽取**：在合格候选池中等概率随机打乱并抽取所需数量的笔记。
4. **全天总量与时段分配**：
   - 全天所需条数 = 推送时段数 × `count`。
   - 例如设置时段为 `09:00` 与 `18:00`，单次数量为 `3`，则全天共抽取 6 条互不重复的笔记；前 3 条分配给上午时段，后 3 条分配给下午时段。
   - 若候选池笔记不足，优先填满前面的时段；候选为空时跳过推送，不发送骚扰空消息。

---

## 三、全天固定计划与多端分发

1. **确定性全天计划**：
   - Core 后台调度在当天首次成功运行时生成全天回顾计划并写入 `state.sqlite3`；Web 首次读取也可触发生成，来源故障时稍后重试。
   - 重启、网页刷新或当日设置修改不会重新抽取计划；规则、时区与时段修改从下一个当地日生效。读取笔记正文时继续复查 Memos 来源。
2. **多端查阅与推送**：
   - **Moerise Web**：进入「每日回顾」页面可随时浏览当天计划的全部笔记，完整展示 Markdown 正文、原图与附件链接，点击可跳转详情页。
   - **Telegram 机器人**：按照配置时段定时推送到私聊或群聊，附带创建日期与标签。
   - **飞书机器人 / Webhook**：按照配置时段定时推送到飞书私聊或指定群聊，长文本智能分片，完整呈现原图。
3. **停机恢复策略**：
   - 停机后恢复仅补建当天最近一次错过时段的发送任务；已经入队的任务按原记录继续恢复，其他时段的笔记仍可在当天 Web 计划中查看。
