# Moerise 每日回顾

每日回顾（Daily Review）每天按规则随机抽取一批历史笔记，方便在 Web、Android 和消息渠道里重新浏览过去的记录。

## 一、核心设计哲学：无压力重温

每日回顾不做任务化设计：

- 不设未读红点或待办数字。
- 不需要标记“已读”或维护打卡天数。
- 每天生成一份固定的回顾清单，在 Web、Android 与消息推送中保持一致，不会随刷新反复跳变。

## 二、候选选取与去重规则

候选筛选与抽样由以下参数控制：

| 参数 | 默认值 | 允许范围 | 说明 |
| --- | --- | --- | --- |
| `count` | `3` | 1 至 20 | 每个推送时段抽取的笔记条数。 |
| `min_age_hours` | `72` | 0 至 87600 | 笔记创建后的等待小时数，新笔记满该时长后才进入候选。 |
| `recent_days` | `7` | 0 至 3650 | 近期去重天数，排除最近若干当地日内已抽中过的笔记。 |
| `include_archived` | `false` | true / false | 是否包含已归档笔记。 |

### 选取流程
1. **基础过滤**：选出属于绑定作者、创建时间满 `min_age_hours` 且最近 `recent_days` 内未被抽中的笔记。
2. **内容检查**：笔记须包含文字正文或图片附件；仅含其他文件附件的条目不占用回顾名额。
3. **随机抽取**：在候选池中等概率随机打乱并抽取所需条数。
4. **全天总量与时段分配**：
   - 全天所需条数 = 推送时段数 × `count`（例如配置 `09:00` 与 `18:00`、`count = 3`，全天抽取 6 条互不重复的笔记，两个时段各分 3 条）。
   - 候选不足时优先填满较早时段；候选为空时跳过发送，不推送空消息。

## 三、全天固定计划与多端分发

1. **固定日计划**：
   - 首次全量同步完成后，Core 后台在当天首次运行时按服务时区生成全天回顾计划并写入 `state.sqlite3`（客户端读取也可触发生成）。
   - 重启、刷新或当天修改配置不会重抽已有计划；规则、时区和时段变更从下一个当地日生效。
   - 客户端与定时投递均从 Core 本地索引读取笔记内容；外部只读接口（`/api/ext/v1/reviews/*`）在读取批次时核验 Memos 来源。
2. **多端查阅与推送**：
   - **Web 与 Android**：进入「回顾」页浏览当天全部条目，点击来源可定位原笔记并直接发起漫步或洞察。
   - **QQ 私聊**：按时段发送可读条数与最多三条短摘录；在 QQ、Telegram、飞书应用私聊发送 `/回顾` 或 `/review` 可随时查询当天计划。
   - **Telegram 机器人**：按时段推送到指定私聊、群聊或频道，包含正文、图片、标签与创建日期。
   - **飞书应用 / 群 Webhook**：按时段推送到私聊或指定群聊，长正文自动分片，按配置支持原图发送。
3. **停机恢复**：
   - 服务停机恢复后，仅补建当天最近一次错过时段的发送任务；已入队的任务按原记录继续处理，其余时段的条目仍可在 Web 和 Android 中浏览。
