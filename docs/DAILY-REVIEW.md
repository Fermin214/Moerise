# 每日回顾

回顾业务由 `internal/reviews.go` 实现。批次、选中历史、打开与略过记录存入 `state.sqlite3`，索引只提供候选；笔记内容始终从 Memos 复查。

REST 与 MCP 共享业务服务和同一账号的产品状态。只读入口读取已有批次；获取或创建、换组、打开与略过使用写入口。路由、工具与访问范围见 [API v1](API-V1.md#每日回顾与-mcp)。

## 选择规则

`review` 配置控制规则，所有值参与规则版本摘要：

| 字段 | 默认值 | 约束与含义 |
| --- | --- | --- |
| `count` | 3 | 每批条数上限，允许 1 至 20 条 |
| `min_age_hours` | 24 | 排除过新的笔记，允许 0 至 87600 小时 |
| `recent_days` | 30 | 排除最近 1 至 3650 个当地日内已选中的笔记 |
| `topic_limit` | 1 | 同一顶层标签的每批上限，1 至 `count` |
| `include_archived` | false | 是否将归档笔记纳入候选 |

候选来自绑定作者的索引。先排除过新、状态不符及近期选中过的资源，按从未选中过、上次选中日期较早排序；同等条件下优先往年同月同日的笔记，再按日期、规则和资源标识的稳定摘要排序。所有顶层标签均参与主题上限，无标签笔记不占标签名额。

选中前复查 Memos 原文、作者、时间、状态与标签，再检查来源身份。已删除、作者不符或过新的笔记不进入新批次。候选不足时返回较少条目或空数组，不通过放宽近期去重或主题上限凑数。

## 批次与记录

批次按来源实例、账号、配置时区、当地日期、规则版本及序号保存。首次获取创建序号 1；相同日期与规则的重复获取返回序号最大的已有批次，不重新选择。时区或规则变化使用独立批次。

只有“换一组”创建后续批次。换组需提供幂等键，范围为账号、日期、时区与规则；同键重试返回该次换组生成的批次，即使之后又换过组。换组同样排除近期已选资源，因此同一天已出现的笔记不会重复。空批次也保持固定。

每个条目保存资源名、选中时的来源摘要与选中时间。打开、略过分别记录首次发生时间，重复操作保持原时间，两种记录可以同时存在。发送记录由通知模块独立保存，推送成功不等于打开。

读取已有批次时再次验证来源身份并逐条获取最新原文。已删除或不再属于绑定作者的资源保留历史位置，响应以 `unavailable: true` 表示，省略正文，不填入新笔记。来源不可用或身份检查失败时整个请求失败，不输出旧正文。

## 恢复

重启后直接读取已有批次。索引重建不删除回顾表；重建期间已有批次仍按资源名复查来源。在线产品状态快照包含全部回顾记录，恢复后沿用批次标识和条目状态。恢复快照之后新增的历史以快照内容为准。
