# Moerise 产品需求文档 (PRD)

---

## 一、产品定位与边界

### 1. 产品概述
Moerise 是基于 Memos 的开源、单用户自托管个人笔记增强产品。Moerise 以 Memos 作为稳固的底层笔记存储底座，围绕记录、阅读、回顾和思考构建完整的个人知识管理体验。Moerise Core 提供回顾调度、语义漫步、认知地图与 AI 深度洞察等扩展能力，并通过 Web 客户端、移动端及第三方消息渠道承接不同场景的日常使用。

### 2. 核心工作原则
- **通用与极简优先**：优先保证核心笔记体验清晰、敏捷与高可靠；个性化偏好通过合理配置满足。
- **尊重原始内容**：所有原生记录入口按用户真实输入原样保存笔记正文与附件，绝不隐式改写正文、不强制格式化、不自动添加文件名或占位符。正文中的 `#标签` 沿用 Memos 原生机制，历史笔记不因规则变动而自动批量改写。
- **AI 洞察定位**：AI 洞察属于独立的思考与启发辅助功能，生成结果与会话历史由用户自行决定是否沉淀并写回 Memos。
- **存储边界明确**：Memos 权威管理原始笔记、标签、图片与附件；Moerise Core 保存向量索引、用户设置、回顾计划与历史、AI 对话会话及消息渠道状态。

### 3. 身份与权限范围
- Moerise 复用 Memos 账户体系进行身份验证，以 Memos 用户身份确定笔记归属。
- 单实例严格绑定一名已认证的 Memos 作者。管理员 PAT 同样受该作者范围限制，绝不越权读取或篡改其他账户数据。

## 二、产品入口与基础笔记体验

### 1. Moerise Web
Moerise Web 提供完整的日常笔记操作与增强功能：
- **时间线与编辑**：沿用浅色两栏式设计，顶部提供快捷编辑卡片，支持 Markdown 写作、附件拖拽与快捷键（`Ctrl+Enter` 保存，`Esc` 取消）；支持在时间线卡片内就地编辑。
- **多维筛选与导航**：左侧栏依次放置导航、搜索、日历和标签树；搜索词、日历月份与标签作为统一筛选条件联动，顶部展示当前已应用条件，支持逐项或全部清除。
- **独立详情页**：每条笔记具备独立 URL 详情页，支持从详情页直接开启“从这条笔记漫步”或“AI 洞察这条笔记”，返回时无缝恢复原视口与筛选状态。
- **基础与增强搜索**：基础搜索使用 FTS5 中文关键词与标签精确匹配，无需模型依赖；语义与混合搜索作为主动开启的增强能力。

### 2. Moerise Android (规划中)
提供完整的移动端随手记与回顾体验，共享 Core 业务接口，支持移动端优化的时间线浏览与离线速记。

### 3. 外部开放生态 (MCP & REST)
为 Claude Desktop、Cursor 等外部 Agent 提供标准 Model Context Protocol (MCP) 只读接口与开放 REST API，仅允许检索与阅读笔记，服务端严格杜绝任何写操作。

## 三、核心功能规格

### 1. 每日回顾 (Daily Review)
- **目标**：以直接阅读旧笔记为核心，唤醒过去记录的闪念与思考，激发全新灵感。
- **选取策略**：
  - **成熟等待期**：笔记创建满设定时长（默认 72 小时）方可进入候选池；
  - **近期去重期**：最近选入回顾的笔记在设定天数内（默认 7 天）自动排除；
  - **内容合格性**：至少包含文字或图片，仅含普通附件且无任何正文/图片的笔记不入池；
  - **归档可配**：用户可选择是否将归档笔记纳入候选。
- **确定性全天计划**：每日凌晨生成固定的全天日计划，依据配置时段（如 09:00、18:00）均匀分配互不重叠的笔记子集，不随刷新打乱。
- **无压力阅读**：不设未读角标、不设打卡连击，阅读与略过均无需点击确认。
- **推送通道**：支持定时推送到 Telegram 机器人或飞书自建机器人/Webhook。

### 2. 随机漫步 (Random Walk)
- **目标**：在笔记库中打破标签壁垒，基于高维语义关联进行思想漫步。
- **交互流程**：可从指定笔记或全库随机起点开始，界面每次展示单条笔记；点击“继续漫步”，系统依据高维向量相似度在合格关联候选内随机挑选下一条。
- **单次漫步去重**：同一次漫步序列中绝不重复走过的笔记，直至候选耗尽或用户主动退出。

### 3. 上下文 AI 洞察 (AI Insights)
- **目标**：多选笔记作为上下文，与大模型展开深度追问、矛盾剖析、假设检验与头脑风暴。
- **材料圈选与预算**：支持手动圈选单条或多条正常/归档笔记，总正文字符规模严格受控（默认 20,000 Unicode 码点以内），防止超出窗口或产生高昂费用。
- **交互与流式输出**：支持 SSE 流式回复、多轮深入追问与主动中断，完整会话持久化存储。
- **成果一键沉淀**：用户可随时将满意的 AI 产出以纯文本/Markdown 形式一键保存回 Memos。

### 4. 认知地图 (Cognitive Map)
- **目标**：通过 2D 语义可视化呈现个人长期的思考重心、知识集群与主题脉络。
- **呈现与交互**：基于高维向量经确定性 PCA 降维投影与局部螺旋避让算法生成二维坐标快照；支持鼠标拖拽平移、滚轮平滑缩放、键盘导航以及点选节点弹窗阅读实时笔记。

## 四、消息渠道与通知系统

1. **飞书应用机器人**：
   - 支持在专属私聊中直接发送文字、图片与文件，自动写入 Memos；
   - 依据每日回顾计划，定时向私聊推送长文本切片与原图。
2. **飞书群自定义机器人 Webhook**：
   - 仅用于定时向指定飞书群推送每日回顾。
3. **Telegram 机器人**：
   - 依据计划定时向指定 Chat ID（私聊或群聊）推送英文标题的每日回顾，长文智能分片并以原文件形式发送图片。
4. **可靠发送状态机**：
   - 维护 `pending`、`running`、`unknown` 与 `sent` 状态机；长正文分片发送，支持网络异常退避重试与人工确认恢复。

## 五、部署与数据架构

1. **部署形式**：
   - 提供一体化 Docker Compose（内置 Memos 0.31.x、Moerise Core 与 Moerise Web）；
   - 支持独立挂接外部已有 Memos 实例；
   - 服务端支持 Linux 原生二进制运行。
2. **数据物理隔离**：
   - `state.sqlite3`：持久化业务状态（加密凭据、用户设置、AI 会话、回顾历史、通知队列），必须列入备份范围；
   - `index.sqlite3`：包含 FTS5 全文索引、向量数据与 2D 地图坐标快照，可随时从 Memos 重新生成。
3. **敏感凭据安全**：
   - 所有模型 API Key 与机器人 Token 采用 AES-256-GCM 加密存储，接口绝不向浏览器回显明文密钥。
