# Moerise｜产品需求文档

来源：[Drive「Agents」中的原文](https://docs.google.com/document/d/1QYrrj_zJ1-bEpbpFmjYF3T0bWL0IADsTRu7ZtuHiyPE/edit)  
修订日期：2026-10-28

## 一、产品定位与边界

### 1. 产品概述

Moerise 是基于 Memos 的开源、自托管笔记产品。Moerise Core 提供回顾、探索、分析和可视化等扩展能力，Web、Android 和消息渠道承接不同场景的日常使用。

Moerise 以 Memos 作为笔记数据底座，围绕记录、阅读、回顾和思考构建完整的使用体验。Moerise 通过 Memos 官方接口扩展产品能力。

### 2. 工作原则

产品面向通用使用者设计，优先实现清晰、可靠的核心体验。使用频率、内容数量、显示偏好等个性化需求通过合理配置满足。功能设计重视实际使用价值与实现成本。

所有原生记录入口按用户输入保存笔记正文和附件，保留内容原貌。笔记可以没有文字正文，仅包含图片或普通文件附件；不自动补文件名、占位说明或其他文字。正文中的 `#标签` 沿用 Memos 原生机制，编辑器显示实际正文，不隐式排序、移动标签或添加标签前缀。历史笔记不因规则调整而自动批量改写。

AI 分析属于独立的洞察功能，相关结果由用户自行决定是否保存。

Memos 管理原始笔记、标签、图片与附件。Moerise 通过官方 API 及必要的 Webhook 对接；Moerise Core 保存语义索引、配置、回顾计划与历史、AI 洞察会话和渠道状态。

### 3. 身份与权限范围

Moerise 复用 Memos 现有账户进行认证，并以 Memos 用户身份确定笔记归属。登录界面采用 Moerise 的产品视觉。

产品以单人自托管为主，一个 Moerise 实例对应一名已认证的 Memos 用户。浏览器会话、服务端 Memos PAT 和外部机器令牌分别管理；管理员身份也不能扩大实例绑定的作者范围。浏览器退出使该次登录失效，不影响后台同步或其他客户端会话。

## 二、产品入口与基础笔记体验

### 1. Moerise Web

Moerise Web 提供完整的日常笔记操作，包括时间线浏览、创建、查看、编辑、删除、标签、附件及基础搜索，并集成每日回顾、随机漫步、AI 洞察、认知地图和设置。

Web 沿用 Memos 熟悉的时间线中心结构，页面上方提供可直接输入、添加标签和附件并保存的编辑区。整体采用浅色、简洁、文字优先的界面风格。

页面布局：所有页面采用左侧栏加内容区的两栏结构。左侧栏依次放置导航、搜索、日历和标签，底部为设置与用户菜单。导航中时间线与每日回顾、随机漫步、AI 洞察、认知地图之间以分隔线区分，不设分组标题。搜索、日历日期和标签作为时间线的筛选条件，在任意页面使用都会回到时间线并应用筛选；时间线顶部显示已应用的筛选条件，可逐项移除或全部清除。附件在笔记内添加和查看，不设独立页面。

笔记详情与编辑：时间线中的笔记在卡片内直接编辑，编辑框与顶部编辑区一致，支持 Ctrl+Enter 保存、Esc 取消。每条笔记有独立地址的详情页，展示完整内容，并提供编辑、从这条漫步、AI 洞察这条和删除操作。回顾、漫步、AI 洞察材料和认知地图中的笔记均可打开详情页，返回时回到来源页面。删除笔记需要二次确认。

时间线与搜索：主时间线默认仅展示正常笔记，按创建时间倒序排列；编辑旧笔记不会使其重新置顶。归档笔记通过独立入口查看和管理。基础搜索使用关键词与标签，不依赖 Embedding；语义和混合搜索作为用户主动选择的增强方式。日期、标签和关键词可组合筛选。

### 2. Moerise Android

Moerise Android 提供完整的移动端笔记体验，包含记录、阅读、管理和扩展功能。客户端共享 Core 的业务能力，以时间线为主要入口，重视移动端的日常操作效率。

### 3. 各入口的职责

Web 和 Android 负责完整笔记管理与扩展体验；飞书承担便捷记录与回顾推送；外部 Agent 通过只读接口获取笔记并开展分析。各入口共享 Core 提供的业务能力。

## 三、核心功能规格

### 1. 每日回顾 Daily Review

目的：让过去记录的闪念、想法、摘录和灵感重新出现在用户眼前，帮助用户重新发现曾经关注的问题和可能的联系。回顾以直接阅读旧笔记为主要体验。

选取规则：从 Memos 的旧笔记中简单随机选取。笔记默认创建满 3 天后进入候选池；最近 7 天内已选入回顾计划的笔记暂时排除，两项时长均可配置。选中即计入排除历史，与实际阅读或推送是否送达无关，用于推荐去重。用户可选择是否包含归档笔记。有正文或图片的笔记可以参与；只有 PDF、压缩包等普通文件且无正文、图片的笔记不进入候选池，不占回顾名额。合格笔记不足时使用实际可选数量；候选为空时不推送。

内容展示：Web 随时展示当天计划的全部笔记，不按推送时段分组，完整呈现正文与图片，并可进入详情查看附件。回顾不设未读数、待办或完成率等提醒，避免形成任务压力；无需手动标记完成，阅读、打开和略过都不是必要操作。

回顾节奏：用户可设置推送时段和每次笔记数量，时段数即每日推送次数。每天生成固定的全天计划，各时段分配不同笔记，不重复抽取。例如 09:00、18:00 各 3 条时，全天选择 6 条，分别推送；候选不足时分配实际可选数量。

多入口一致：全天计划由 Core 固定生成，Web 读取全部结果，已启用的推送渠道读取对应时段的分配。刷新、重启、切换入口或修改设置都不替换当天计划，设置变更从后续日期生效。取消“换一组”，保留必要的历史批次读取与恢复能力。

停机恢复：当天错过多个推送时段时，只补发最近一次，不集中补发其余错过时段；跨日不补建往日计划。已经入队的任务继续按发送恢复机制处理。

展示渠道：Web 负责站内回顾，飞书负责可选的主动推送。Core 统一管理回顾选取、记录及推送计划。

### 2. 随机漫步 Random Walk

目的：让用户主动在旧笔记之间游走，发现意料之外的关联。漫步在一定语义联系的基础上保留随机性，鼓励跨主题的思想碰撞。

交互与选取：用户可以随机开始，或指定一条笔记作为起点。界面每次展示一条完整笔记，点击“继续漫步”后选择下一条。候选来自与正在展示的笔记有一定联系的内容，并以随机方式选择；同次漫步避免重复，用户可随时停止。

关联方式：结合语义检索结果随机选取下一条笔记，允许不同强度的关联。每次前进由用户主动触发，逐条展开漫步过程。

概率与路径：不按标签相同施加主题偏好，也不因笔记近期在回顾、时间线或其他入口被阅读而降低概率。同次漫步不重复已经访问的笔记，不设固定的产品路径长度上限。达到技术资源限制与没有合格候选应分别反馈。

### 3. AI 洞察 AI Insights

目的：使用 AI 探索笔记之间的联系、思想变化、潜在矛盾、盲点和新的可能性；用户也可以围绕选定笔记自由提问。

分析范围：支持手动选择单条或多条笔记，也可通过日期范围、标签及组合条件选择。用户明确选中的笔记全部作为分析材料，包括归档笔记；日期、标签等条件用于选材，提交后不再次静默过滤，也不自动加入全库材料。来源已删除、失去访问权限或已失效时，需检查并反馈材料状态。

使用方式：提供“一键洞察”和自由提问两种入口。“一键洞察”使用内置默认 Prompt；默认 Prompt 可查看、修改并恢复默认。自由提问以所选笔记作为材料。

连续讨论：采用以消息交流为中心的自然聊天，支持流式输出、追问和深入探索。所选笔记与对话上下文随会话持久保存，刷新或重新进入后可继续讨论，用户可以主动删除会话。分析风格鼓励联想、质疑、提出假设和多种解释，并自然区分笔记原意与 AI 新提出的想法。

结果保存：AI 回复和对话历史是独立的产品会话数据，不自动写入 Memos。用户可以将选中的回复主动保存为 Memos 笔记；也可以先让 AI 总结对话，再保存总结结果。保存保留所选内容，不自动改写正文或添加标签。

输入规模：展示已选笔记数量，并通过简单的总字符数限制控制输入规模。超过限制时提示用户调整选择范围。

服务范围：Moerise 不提供独立结构化洞察、笔记问答或主题时间线生成服务。Web 聊天复用通用 LLM Provider、模型通信和流式能力；外部 Agent 自行使用其模型分析只读获取的笔记。

### 4. 认知地图 Cognitive Map

目的：通过可视化方式呈现长期积累的思考重心、笔记主题分布及内容密集区域。

呈现与交互：使用二维语义地图，每个点代表一条笔记，语义相近的笔记在空间上相互靠近。用户可以平移、缩放地图，点击点位阅读对应笔记。布局应在实际使用中保持稳定、清晰。

## 四、消息渠道、Agent 与模型

### 1. 飞书机器人

飞书机器人是可选的便捷记录与每日回顾渠道，提供专用私聊交互以及定时推送。

私聊记录：用户直接发送文字或图片即可创建笔记，系统将输入内容原样写入 Memos，并给出简洁的成功或失败反馈。机器人仅处理专用私聊中的记录请求。每日回顾按照用户设定的计划主动发送，与 Web 共享当天回顾内容。

渠道接入：飞书应用机器人承担双向记录与回顾推送；仅需消息通知的场景可接入支持发送消息的 Webhook。Webhook 允许只配置 URL 的纯文字模式；完整图文推送需要相应图片发送能力，设置界面明确展示渠道能力。

内容适配：文字版 Webhook 遇到纯图片笔记时直接跳过；图文笔记只发送文字，不额外提示，也不重新抽取补足数量。普通文件不推送。发送期间来源笔记被修改、删除或失去访问权限时，停止发送该笔记的剩余内容，不额外提示。

发送恢复：对结果不明的发送保留暂停、确认和恢复能力，通过日志与管理接口处理，不建设专门的 Web 异常消息管理页。保留数据库迁移、旧数据识别和未完成任务恢复；删除失效的旧命令交互与操作提示，不恢复已取消的聊天命令。

### 2. MCP 与外部 Agent

Moerise 通过通用 MCP 接口向外部 Agent 提供笔记获取与搜索能力，由调用方自行使用其模型分析。对外 MCP 和机器接口只读，不开放笔记或产品状态写入，即使机器令牌包含写入 Scope，也不能创建、修改、删除笔记或改变回顾计划。

Web、Android 和专用记录机器人承接用户主动执行的笔记写入操作，内部受控服务保留必要写入与运维恢复能力。外部机器令牌不能代替原生客户端会话或内部凭据。机器检索与列表的默认模式、排序可独立管理，不要求与 Web 默认值相同。

### 3. 模型依赖

Embedding 与 LLM 可分别配置，并通过通用模型接口接入服务。Embedding 用于语义索引、随机漫步与认知地图；LLM 用于 AI 洞察和连续追问。语义索引支持更新与重建。

模型及飞书等消息渠道按需启用。基本笔记记录、编辑、搜索、时间线和每日回顾可独立运行；需要模型或消息渠道的功能在配置完成后启用。

## 五、部署、设置与数据

### 1. Core 与部署形式

Moerise Core 负责与 Memos 同步、状态持久化、语义与回顾计算、推送协调，以及 REST/MCP 接口。各客户端通过共享服务使用相关能力。

部署方式包括连接现有 Memos 的独立扩展部署，以及通过 Docker Compose 同时部署官方 Memos、Moerise Core 和 Moerise Web 的一体化方案。组件保持独立，分别维护和升级。

### 2. 安装与配置体验

部署文档提供必要参数说明，以及安装、启动、重启和基本升级的操作步骤。

配置分层：Memos 连接信息、服务地址、启动鉴权等基础设施参数放在 .env；每日回顾频率、时间、数量、等待期、重复排除期、归档开关、模型选择及默认洞察 Prompt 等日常设置在 Web 中管理并持久化。

Web 设置支持管理模型 API 地址、模型选择、API Key、飞书机器人与 Webhook 凭据。保存后即可由服务端使用。密钥由服务端安全保管，界面展示配置状态或遮蔽信息。

配置在重启、正常升级和索引重建后保持。模型变更更新相应服务资源；更换 LLM 无需重建语义索引，Embedding 变更须保持索引与模型一致。渠道设置展示文字或图文能力及所需配置。

### 3. 数据与备份边界

Memos 保存原始笔记数据，Moerise 保存扩展功能所需的索引、设置、回顾计划与历史、AI 洞察会话和渠道信息。AI 会话属于需持久保存的产品状态，遵循用户主动删除规则。

旧渠道 AI 结果完成发送及确认后，清理不再需要的内容副本，保留防重复、确认和恢复必需的元数据；该清理规则不用于 Web AI 会话。必要迁移、旧数据识别和未完成任务恢复随升级保留。

更新或卸载说明提供备份与数据导出的简短提醒，用户可以使用 Memos 已有的数据导出和备份方式。

## 六、实施与版本规划

MVP 范围：优先交付完整可用的个人笔记体验，复用 Memos 账户，支持单人部署。每日回顾采用全天固定计划与分时分配，随机漫步支持关联候选内随机的连续单条探索，AI 洞察提供可编辑默认 Prompt、自由提问和持久会话，认知地图采用二维语义分布。多用户、复杂管理界面及大型视觉改版列入后续。

部署安排：首个完整产品版本同时交付完整 Web 与一体化 Docker Compose。首次部署采用 README、.env 和 docker compose up -d。飞书阶段先使用环境配置，Web 交付后提供浏览器设置。

开发顺序：① Core → ② 飞书 → ③ 完整 Web（含一体化部署）→ ④ Android。各阶段交付可独立验证的功能，Core 随后续功能需求逐步增强。

### 阶段一：Core

验收：连接实际运行的 Memos，验证基础同步、必要接口、状态持久化和认证。创建、修改笔记后检查同步结果，并验证服务重启后的运行状态。

### 阶段二：飞书

验收：通过飞书专用私聊发送笔记，确认 Memos 保存原文；按设置收到每日回顾，并验证候选为空时的行为。

### 阶段三：完整 Web 与 Compose

验收：在 Moerise Web 中完成笔记创建、阅读、编辑、删除、标签和纯附件操作，验证正文原样保存、默认时间线和搜索、固定回顾分时分配、漫步去重、AI 会话恢复与删除、主动保存、认知地图和设置。通过 Compose 验证新环境部署、数据持久化、基本升级与权限隔离，并完成旧接口及恢复兼容清理。具体交付顺序与依赖以 [ROADMAP](ROADMAP.md) 为准。

### 阶段四：Android

验收：在真实 Android 设备上完成基本笔记管理和扩展功能的实际使用验证。具体技术路线在该阶段选定。

阶段完成标准：必要的自动化测试通过，并在实际运行的服务和客户端上走通该阶段的核心使用流程。

## 七、未来需求候选与实施待定事项

### 1. 已认可的长期候选

每日回顾：历史上的今天、沉睡的灵感、主题漫游、智能权重和更多筛选策略。

随机漫步：调节关联紧密程度、临时换方向、完全无关跳转、走过的路径，以及结束后的“思想漂流”回看。

AI 洞察：经用户主动启用、带范围与成本限制的全库主题检索；多套 Prompt 和分析视角。

认知地图：主题区域命名、时间轴、漫步路径叠加，以及地形/等高线/3D 等新呈现。

客户端平台：支持 iOS、Windows、macOS，扩展 Moerise 的多平台使用范围。

其他扩展：Telegram、QQ、微信等消息渠道；Android 离线记录、本地优先和多端同步；多用户与独立账户体系；按实际需求扩展底层架构。图形化安装向导与其他运维工具也可在后续评估。

### 2. 实施时确定的细节

每日回顾：推送时段和数量的默认呈现、候选不足时的时段分配顺序，以及渠道长内容的具体呈现方式。

随机漫步：具体弱关联抽样方法、候选不足时的行为、返回上一条的交互。

AI 洞察：总字符数上限的初始值及不同客户端的输入细节。

认知地图与 Android：布局实现和真实可读性验证；Android 是复用既有开源客户端还是新建原生实现，开发阶段再做技术选型。
