# 语义检索与发现验收

阶段 3 的交付包括向量模型、分块索引、中文混合检索、相关笔记、语义漫步，以及效果与资源测量。2026 年 10 月 27 日的测量使用 Go 1.27.3、Linux amd64、Memos 0.31.0 和百炼 `qwen3.7-text-embedding`，向量维度为 1024。

## 验收结论

阶段 3 的工程交付和固定问题集效果评测均通过验收。语义与混合检索的 Hit@5 均为 0.95，MRR@5 分别为 0.860、0.681，达到问题集预先固定的门槛，且无请求错误或语义降级。相关笔记、三种漫步、跨入口一致性、来源变更与故障、重启和恢复流程均通过验证。

首次索引、查询延迟与资源测量已完成，支持批量 20、模型并发 2 的默认配置。效果结论适用于 67 条工程笔记和 20 个同领域问题；个人笔记库的检索与发现效果使用对应语料另行评估。一万条合成向量基准用于衡量本地计算、索引和内存成本。

## 问题与语料

语料固定在提交 `86d9173f2b350dee13538156b56745f9bf2e9110` 的八篇工程文档：运行与恢复、API v1、每日回顾、飞书、通知、向量模型、搜索、产品与架构。按二、三级标题拆成 67 条独立笔记，保留标题与正文，按文档添加主题标签，生成 69 个正文片段。笔记经官方 API 导入独立 Memos，再由真实服务同步、分块和构建索引。

[问题集](../tests/testdata/stage3-questions.json)包含 20 个工程使用问题，涉及备份恢复、写入去重、推送、回顾、检索模式、作者隔离、来源变化和漫步。问题、期望章节及通过条件在模型调用前固定；语义与混合模式分别要求 Hit@5 至少 0.85、MRR@5 至少 0.60，且无错误或降级。关键词模式作为基线。期望结果是章节引用，运行时映射为笔记资源名；完整命中顺序与语料 SHA-256 保存在[实模型结果](evidence/stage3-live.json)。

这组数据衡量工程文档中的自然语言检索。私人笔记、其他领域和不同长度分布可使用[开发指南](DEVELOPMENT.md#检索评测)中的自定义问题集另行测量。

## 实模型检索

每题依次执行 `keyword`、`semantic`、`hybrid`，每次返回前五条。延迟包含真实百炼请求、REST 传输、排序和 Memos 来源复查；请求间的节奏控制不计入延迟。

| 模式 | 命中问题数 | Hit@5 | MRR@5 | 中位延迟 | P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| keyword | 13/20 | 0.65 | 0.488 | 20.4 ms | 23.7 ms |
| semantic | 19/20 | 0.95 | 0.860 | 163.9 ms | 220.7 ms |
| hybrid | 19/20 | 0.95 | 0.681 | 167.7 ms | 241.9 ms |

Hit@5 为前五条结果中至少出现一个期望章节的问题比例，0.95 对应 20 题中的 19 题。第一条结果的准确率需单独统计。MRR@5 为首个期望结果名次倒数的平均值，前五条未命中按零计，数值越高表示正确结果越靠前。

60 次请求全部成功，语义与混合模式均实际使用模型。语义模式未命中的第 9 题询问关闭模型后的搜索，前五条为混合搜索与接口概述；混合模式未命中的第 17 题询问飞书漫步，被回顾和飞书交互章节挤出前五。两题继续保留在问题集中。

语义模式在这组改写问题上的排序优于混合模式。混合检索达到验收门槛，融合后的正确结果排名仍有优化空间。默认混合模式继续提供关键词、标签与语义的共同召回；调用方可显式选择语义模式。

## 相关笔记与漫步

分别以“重建索引”和“每日回顾选择规则”为起点，检查相关笔记前五条和三种各三步的漫步。结果均来自导入语料，相关结果排除自身，漫步不重复路径中的资源。

| 起点 | 操作 | 实际路径 |
| --- | --- | --- |
| 重建索引 | 继续话题 | 重建索引 → 恢复产品状态 → 备份产品状态 → 备份与恢复 |
| 重建索引 | 换个角度 | 重建索引 → 搜索的索引迁移与恢复 → 架构的数据与身份 → 存储与备份范围 |
| 回顾选择规则 | 继续话题 | 选择规则 → 批次与记录 → 回顾恢复 → 恢复产品状态 |
| 回顾选择规则 | 换个角度 | 选择规则 → 每日回顾与 MCP → 搜索的相关笔记 → 相关笔记 API |

“重建索引”的相关结果包括恢复、运行检查、升级、备份和部署；“选择规则”的前三条相关结果分别是批次记录、回顾恢复及回顾接口。路径体现了继续相近内容和跨模块查看相关内容的区别。换角度按每一步的语义与主题权重选择，允许再次进入某个主题，路径去重以笔记资源为单位。

随机路径遍历了创建流程、关键词排名、模型配置、备份和接口等章节；随机模式每次可返回不同结果，完整采样见结果 JSON。两组相关请求与 18 步漫步的前后模型调用计数相同，均复用文档向量或随机候选。

## 一万条向量基准

[性能结果](evidence/stage3-benchmark.json)使用同一型号 CPU、Go 1.27.3 和 `GOMAXPROCS=2`，生成 10,000 条不同短笔记及 10,000 个稠密、1024 维 float32 向量。模型和 Memos 使用进程内实现，便于分开观察本地计算、SQLite 和缓存成本；这里的吞吐量不包含网络与供应商限流。

| 场景 | 样本数 | 结果 |
| --- | ---: | --- |
| 首次索引，批量 5 | 1 | 26.25 s，2,000 批，峰值 RSS 41.4 MiB |
| 首次索引，批量 20 | 1 | 8.67 s，500 批，峰值 RSS 43.8 MiB |
| 应用向量缓存冷启动 | 10 | 平均 158.9 ms，P95 197.4 ms |
| 热缓存语义候选扫描 | 100 | 平均 13.6 ms，P95 16.5 ms |

首次索引从已有投影开始，包含向量生成、批次持久化和代次发布，不计入笔记投影导入。冷启动每次创建新的应用向量缓存，操作系统文件缓存可能已热；热扫描预先载入活动矩阵。矩阵向量本体为 39.1 MiB，GC 后净保留堆为 42.9 MiB；测量进程含夹具、SQLite 和 Go 运行时，各场景峰值最高约 149.4 MiB。批量 20 的索引数据库、WAL 与 SHM 合计约 116.9 MiB。

完整 Search 服务基准包含融合、身份检查和十条来源原文复查，每组执行 50 次。延迟从工作线程开始处理请求计时，不包含工作线程排队：

| --- | ---: | ---: | ---: |
| semantic | 1 | 50.90 次/s | 22.2 ms |
| semantic | 2 | 100.90 次/s | 25.8 ms |
| semantic | 4 | 104.50 次/s | 61.4 ms |

## 配置结论

- 保持 `batch_size=20`。真实 69 片段语料的模型批次从 7 减至 4；一万片段基准中，批量 20 相比批量 5 减少 75% 的模型请求批次，索引耗时约为三分之一。
- 保持 `max_concurrency=2`。真实请求达到该上限后正常排队，四路调用的 P95 上升到约 397 ms；本地两线程基准中增加到四路查询也几乎不再增加吞吐。该参数约束模型批次，不是 HTTP 请求总数。
- 一万条、每条一个 1024 维向量时继续使用内存精确检索。部署可从 2 vCPU、512 MiB 内存起步，按实际片段数和峰值 RSS 调整；长笔记的片段数决定向量占用。
- 请求并发还要考虑 Memos 的来源复查预算。模型并发不能替代来源限流规划，不通过省略身份或原文检查提高吞吐。
